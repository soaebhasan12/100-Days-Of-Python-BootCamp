### **Lecture Breakdown: Using Jinja to Produce Dynamic HTML Pages**

**Learning Objectives:**
*   Set up a basic Flask app to render an HTML template.
*   Understand and use Jinja syntax (`{{ ... }}`) to embed Python expressions directly in HTML.
*   Pass variables from the Flask server to the HTML template using `render_template()`.
*   Create dynamic content that changes on each page load or is calculated programmatically.

**Explanation for Beginners:**

1.  **From Strings to Templates:** We start by moving away from returning raw HTML strings (`return "<h1>Hello</h1>"`) in our Flask routes. Instead, we use the `render_template()` function to send a separate HTML file.

2.  **The `templates` Folder:** This is a magic folder name. Flask *automatically* looks inside a folder named `templates` for any HTML files you ask `render_template()` to find. You **must** create this folder.

3.  **Jinja Syntax - `{{ }}`:** This is the most basic Jinja syntax. Anything you put inside double curly braces `{{ }}` is treated as a Python expression. Jinja calculates the result and inserts it into the HTML in that exact spot.
    *   Example: `{{ 5 * 6 }}` in the HTML becomes `30` in the final web page.
    *   Without the `{{ }}`, it's just treated as plain text: `5 * 6`.

4.  **Passing Data from Server to Template:** The real power comes from sending Python variables from your Flask app to the template. This is done using **keyword arguments** in the `render_template()` function.
    *   **Syntax:** `return render_template('index.html', variable_name_in_html=variable_name_in_python)`
    *   **Example:** `return render_template('index.html', num=random_number, year=current_year)`
    *   Now, in `index.html`, you can use `{{ num }}` and `{{ year }}` to display those values.

5.  **Dynamic vs. Static:** The page's structure (headers, footers, styling) remains **static** in the HTML file. The content inside the `{{ }}` placeholders is **dynamic**—it's generated by your Python code on the server each time the page is requested. This is why you get a new random number on every refresh.

**Notes for Notebook:**
*   **Folder Structure:**
    ```
    my_project/
    │   server.py
    │
    └───templates/
            index.html
    ```
*   **Import:** `from flask import Flask, render_template`
*   **Render HTML:** `return render_template('filename.html')`
*   **Jinja Expression:** `{{ python_expression }}` e.g., `{{ name }}`, `{{ 2+2 }}`
*   **Pass Variables:** `render_template('index.html', key1=value1, key2=value2)`

**Key Interview Points:**
*   **Q: What is the purpose of the `render_template()` function in Flask?**
    *   **A:** It generates a complete HTML page by processing a template file (usually containing Jinja syntax) with any provided context variables. It separates the application logic (in `.py` files) from the presentation logic (in `.html` files).
*   **Q: How do you pass a variable from a Flask route to a Jinja template?**
    *   **A:** You pass them as keyword arguments to the `render_template()` function. For example, `render_template('user.html', username=user_name)` makes a variable `username` available inside the `user.html` template.
*   **Q: What is the difference between `{{ ... }}` and `{% ... %}` in Jinja? (Hint for next lecture!)**
    *   **A:** `{{ ... }}` is used for **expressions** that output a value directly into the HTML. `{% ... %}` is used for **statements** that control the template's logic, like loops and conditionals (which don't output a value directly).

**Common Mistakes & Updates:**
*   **Mistake:** Putting the `templates` folder in the wrong location. It must be in the same directory as your main Python script (e.g., `server.py` or `app.py`).
*   **Mistake:** Forgetting to import `render_template` from `flask`.
*   **Update/Clarification:** The lecture uses `datetime.datetime.now().year` to get the year. This is correct. An alternative is to use `datetime.date.today().year`, which is slightly more explicit if you only need the date. Both are perfectly valid.
